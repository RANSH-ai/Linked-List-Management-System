===========================================================================
           COMPREHENSIVE COMPARISON: SINGLY VS DOUBLY LINKED LIST
===========================================================================
CRITERIA / PROPERTY      | SINGLY LINKED LIST (SLL) | DOUBLY LINKED LIST (DLL)
---------------------------------------------------------------------------
Node Structure           | Data + Next reference   | Data + Prev + Next references
References per Node      | 1 pointer (next)        | 2 pointers (prev, next)
Memory Overhead          | Lesser (saves pointer space) | Higher (~33%-50% more memory)
Traversal Direction      | Forward only (unidirectional) | Bidirectional (forward & back)
Insert at Head           | O(1)                    | O(1)                   
Insert at Tail           | O(n) [O(1) with tail ref] | O(1) with tail reference
Delete Head              | O(1)                    | O(1)                   
Delete Tail              | O(n) (needs predecessor) | O(1) with tail reference
Delete Given Node Ref    | O(n) without prev node  | O(1) directly via prev/next
Insert Before Given Node | O(n) without prev pointer | O(1) using prev link   
Reverse List             | O(n) time, O(1) space   | O(n) time, swap prev/next
Implementation Effort    | Simpler, fewer pointer bugs | More complex, double links
Real-World Use Cases     | Hash table chaining, Queues | Browser history, LRU Cache
===========================================================================
Key Takeaway:
ò Use Singly Linked List when memory conservation is prioritized and backward
  traversal is never required.
ò Use Doubly Linked List when frequent deletions of known nodes or two-way
  traversal (e.g. undo/redo, browser navigation) are needed.
